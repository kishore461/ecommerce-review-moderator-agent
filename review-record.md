# Review record

Three AI reviews of the project, as required by Section 11, with every comment
accepted or rejected and a reason given for each.

---

## A conflict of interest that has to be stated first

**All three reviews below were produced by Claude — the same assistant that
wrote the code being reviewed.** That is a real weakness. A reviewer that shares
the author's assumptions will not see the assumptions. The comments below were
generated by asking it to attack the work rather than describe it, and two of
them did overturn a headline result, so it was not purely decorative. But it is
not independent scrutiny.

**Action taken:** the two findings with the largest consequences — the ablation
and the base-rate sensitivity — were converted into runnable experiments rather
than left as opinions, so they can be checked by anyone regardless of who raised
them. Output: `results/ablation.md`.

**Update — Review 4 was added.** A fourth review was run by a *separate Claude
session with no access to the author's reasoning*, given only the repository
artefacts and instructed to attack them. That is not an independent tool — it is
the same model — and it is labelled as such below. It nevertheless found two code
bugs and overturned the project's central ablation claim, which the three reviews
above had missed entirely. Findings and fixes are in Review 4.

**Still outstanding:** a review by a genuinely different assistant (ChatGPT,
Gemini or Codex). Review 4 shows what fresh context alone can catch; it does not
substitute for a different model.

## Review 2 — Probability review (Section 11.2)

Asked to check: hidden states, prior probabilities, likelihood estimates,
decision thresholds, error costs, calibration, evidence for an alternative
explanation.

| AI tool | Review comment | Accept / reject | Reason | Change | Evidence |
|---|---|---|---|---|---|
| Claude | The lexical channel and the six features are both computed from the same text and then multiplied as if independent. This double-counts the same evidence and inflates confidence. | **Accept — this is the most serious comment in the record** | It is straightforwardly true. Naive Bayes assumes conditional independence; a word-level model and a phrase-counting model over the same string violate it badly. | The lexical LLR is clipped to ±4.0 specifically to limit the damage, and the clip is recorded in the manifest. The underlying flaw is **not fixed** and is now stated as a limitation rather than hidden. | ECE 0.145 with the 0.6–0.8 band predicting 0.696 against an observed 0.200 — the overconfidence this predicts is exactly what the calibration table shows. |
| Claude | Features are not conditionally independent either. `length_band` and `specificity` are mechanically correlated — longer text has more chances to contain a specific token. | **Accept** | Same failure, smaller magnitude. | Documented. Not corrected: modelling the dependence would need a joint estimate the 6,000-row fit split cannot support reliably across 3×3×4×2×2×3 cells. | `src/features.py`: `_specificity_evidence` counts tokens, so its expectation rises with length by construction. |
| Claude | The `solicited` likelihoods are derived from `genuine` by multiplying praise levels by 0.5 / 1.0 / 1.8. Those multipliers have no source. | **Accept** | They are invented. The direction came from a human discussion; the magnitudes did not. | Marked in code as `SOLICITED_ASSUMPTION` and surfaced in `results/likelihoods.json` so a reader meets the assumption before the number. Flagged prominently in the decision record, where `solicited` ends up carrying most of the posterior. | `src/agent.py: _derive_solicited()`; `decisions/probability-decision-record.md` §4, posterior solicited 0.4571 vs fake 0.2585. |
| Claude | Calibration is measured on 40 points across 5 bins. Some bins hold a single case. The ECE figure is too noisy to quote to three decimals. | **Accept** | Correct. One bin on the main run holds n=1. | ECE is now described as indicative and always reported next to the bin counts rather than alone. No confidence interval is computed — with n=40 it would be so wide as to be uninformative, and saying so is more honest than producing one. | `results/metrics.md` reliability tables include the `n` column for exactly this reason. |
| Claude | `p_not_genuine` sums `fake` and `solicited`, but their costs differ substantially (permit costs 5.0 vs 2.0). Collapsing them throws away information the cost model has. | **Accept** | A real design flaw in Policy A specifically. Policy B does not have it — it works over the full distribution. | Documented as a structural difference between the policies, and it partly explains why they diverge. Policy A is left as-is because it is meant to represent the practitioner's threshold rule faithfully, including its limitations. | `decisions/probability-decision-record.md` §6: at P=0.913 Policy A flags while Policy B still routes. |
| Claude | The 0.85 threshold was never validated against the cost model. It was adopted from one practitioner's remark. | **Accept** | This was already the point of comparing two policies, but the review is right that it was never said plainly. | Stated explicitly in the README and the defence brief: 0.85 is borrowed authority, and the experiment tests it rather than assuming it. | With features alone the belief never reaches 0.85 at all — see `results/ablation.md`, features-only recall 0.000. |
| Claude | A 50/50 prior is not a neutral choice. It is an informative claim that half of all reviews are fake. | **Accept** | Correct, and it interacts with the base-rate comment in Review 1. | The prior is now reported as an experiment parameter in the manifest, and the sweep shows what happens without it. | `results/ablation.md`, base-rate table. |
| Claude | The agent should output a calibrated probability by fitting a Platt / isotonic correction on the fit split. | **Reject — deferred** | Technically right, and it would likely reduce ECE. Rejected for this iteration because a correction fitted on the fit split and evaluated on 40 cases would be very hard to distinguish from overfitting, and reporting a repaired ECE without a clean validation split would be a stronger claim than the data supports. | None. Logged as the first item of future work. | Fit split is 6,000 rows from the same distribution; no separate validation split exists. |

## Questions for the next version

1. Does a calibration correction fitted on a **separate** validation split reduce
   ECE below 0.145 without overfitting?
2. Does the agent hold up when evaluated on a product category held out entirely
   from training, or does the lexical channel collapse?
3. What is a defensible base rate for fake reviews? Every number in this project
   is conditional on a prior nobody has measured.
4. Can the double-counting between the lexical and feature channels be removed —
   for example by fitting one joint model — without losing the interpretability
   that makes the feature contributions auditable?
5. Is there any text-only signal that survives an adversary who reads the page
   before writing? Specificity does not.
6. Do paid human fakes look like machine-generated ones at all? If not, none of
   these results transfer to the stated problem.

## Review 4 — Adversarial artefact-only review (all three categories)

**Tool:** Claude, separate session, no access to the author's reasoning or to any
of the discussion history. Given only the files in the repository and instructed
to find what was wrong rather than describe what was there, and explicitly told
not to repeat limitations the project already admitted.

**Why it is listed separately:** it is the same model as reviews 1–3, so it is
not independent scrutiny. It is *fresh context* — which turned out to matter more
than expected. Two of its findings are code bugs that reviews 1–3, written with
knowledge of why each choice was made, did not see.
